How This Forked System Works

Architecture Overview
1

Metadata Repository Blockchain (Port 8545)

Hosts the StoreForkEvent contract. It maintains the registry of every fork event and builds an adjacency list mapping parent chains to child branches.

2

Independent Data Chains (Ports 8546–8551)

Each blockchain is an isolated EVM network running its own BlockData contract. Data points can be added at any block height on any branch.

3

Fork Provenance & Fork Blocks

When Chain B forks from Chain A at block $H$, Chain B inherits historical data up to block $H$, while creating an independent branch for subsequent transactions.

4

Cross-Chain DFS Traversal Search

Queries the repository for the fork graph adjacency list, then recursively visits branches in Depth-First Search order, calling smart contract search methods on each target chain.

On-Chain Multi-Algorithm
BFS Breadth-First Search

Visits nodes level-by-level across the hierarchy (Level 0 Root → Level 1 Forks → Level 2 Sub-forks). Ideal for finding values residing closest to the origin or main chain.

DFS Depth-First Search

Dives deep into child branches before backtracking (Root → Alpha → Gamma → Delta → Beta → Epsilon). Follows specific lineage chains to their tip before trying siblings.

How Fork Spawning Works

System Architecture
1

Single Root Origin

Chain 11102 (Port 8546) is the single immutable root blockchain. All other chains in the system are forked blockchains that inherit parent state up to their designated fork block height.

2

Zero-Downtime Dynamic Port Allocation

The multi-chain engine dynamically assigns an unused port (e.g. 8552, 8553) and starts a new isolated JSON-RPC server on localhost without restarting the existing nodes.

3

Automatic Smart Contract Provisioning

A fresh BlockData.sol contract is deployed to the new chain. The parent-child fork edge is simultaneously logged in the central StoreForkEvent.sol repository on Port 8545.

4

Live Visual & Traversal Integration

As soon as the node is spun up, the interactive SVG tree topology graph adds the new node, the node monitor tracks its block height, and both BFS/DFS algorithms will traverse it.
